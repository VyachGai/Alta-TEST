# Таблица товаров для «Заполнителя» (Альта-Софт)

Веб-приложение для специалиста по таможенному оформлению. Состоит из трёх разделов:

1. **Таблица товаров** — из загруженных коммерческих документов (инвойс, упаковочный лист, спецификация) собирает единую таблицу товаров для последующего импорта в программу «Заполнитель» разработчика Альта-Софт.
2. **Проверка ограничений** — сверяет коды ТН ВЭД с перечнями постановлений Правительства РФ 311, 312 и 313.
3. **Маркировка «Честный знак»** — сверяет коды ТН ВЭД со сводным перечнем товаров, подлежащих маркировке средствами идентификации, и добавляет к таблице оператора одну графу с выводом.

Все разделы работают целиком в браузере: документы **не отправляются ни на какой сервер** и обращений к внешним сайтам нет (кроме опционального распознавания через ИИ в первом разделе — см. ниже). Это важно при работе с коммерческими документами.

## Правила обработки

- **Поиск данных** ведётся по ключевым словам в заголовках колонок и тексте документов: *наименование, название, модель, артикул, изделие, код изделия, вес нетто, вес брутто, цена, стоимость, количество, ед. изм., грузовое место* и их англоязычные аналоги (*description, article, model, net weight, gross weight, price, amount, qty, place, box* и т. п.).
- **Наименование товара** разносится по двум графам, таблица всегда остаётся русскоязычной:
  - в документе наименование дано на двух языках — русский текст идёт в графу «на русском языке», иностранный в графу «на иностранном языке». Распознаётся и запись в одной ячейке (через «/», в скобках, второй строкой), и **раскладка счёта-фактуры, где на каждый товар идут две строки подряд — русская и её английский перевод** с тем же количеством, ценой и стоимостью: такие строки склеиваются в одну, английское наименование попадает в свою графу, количество и суммы не удваиваются;
  - только на русском — графа «на иностранном языке» остаётся пустой;
  - только на иностранном — исходный текст идёт в графу «на иностранном языке», а в графу «на русском языке» подставляется **машинный перевод**, и в замечаниях заполнителя появляется предупреждение *«машинный перевод, проверьте его правильность!»* (строка выделяется жёлтым).

  Перевод выполняет Claude, поэтому он доступен только при запуске через `npm start` (см. «Распознавание с ИИ»). Без сервера графа «на русском языке» для иноязычных наименований остаётся пустой — об этом появляется отдельное замечание.
- **Коды единиц измерения** проставляются по классификатору ОКЕИ (шт → 796 / ШТ, кг → 166 / КГ, компл → 839 / КОМПЛ, пар → 715 / ПАР и др.). Если единица не распознана, соответствующие графы остаются пустыми.
- **Брутто грузового места** распределяется между товарами этого места **пропорционально их весу нетто**, с округлением до трёх знаков после запятой (остаток округления относится на последний товар места, поэтому сумма всегда сходится с брутто места).
- **Брутто берётся с паллетами.** Если упаковочный лист даёт две колонки брутто — без паллет и с паллетами («TOTAL GW/KG without Pallet» и «TOTAL GW/KG with pallets», «вес брутто с поддонами») — в таблицу идёт вес **с паллетами**: именно он предъявляется на границе.
- **Повторяющиеся товары** (одинаковое наименование и артикул) объединяются в одну строку; количество, стоимость и веса суммируются. Если товар лежит в нескольких местах, номера мест перечисляются через запятую.
- **Что считается одним товаром.** Кроме наименования и артикула учитываются **модель и цена за единицу**. Инвойсы на технику называют все строки одинаково («Mobile phone»), а товар различает графа «Модель» — без неё вся страница инвойса схлопнулась бы в одну позицию. Одна и та же модель, отгруженная по разным ценам, тоже остаётся разными строками: так сохраняется равенство «цена × количество = стоимость», которое проверяет «Заполнитель».
- **Вес из упаковочного листа переносится на строки инвойса по модели.** Упаковочный лист часто даёт одну строку на модель («MAXVI C27i» — 40 000 шт), а инвойсы разбивают её по цвету и цене; наименования при этом не совпадают вовсе. Программа сопоставляет их по модели (марка из начала отбрасывается, цвет в конце допускается) и раскладывает нетто и брутто между строками инвойса пропорционально количеству. Перенос выполняется, только если **сумма количеств строк инвойса в точности равна количеству из упаковочного листа** — иначе строки остаются раздельными, чтобы не приписать вес не тому товару.
- **Порядок строк задаёт инвойс** (счёт-фактура, спецификация) — именно он определяет нумерацию товаров в декларации, тогда как упаковочный лист перечисляет те же товары в порядке раскладки по грузовым местам. Порядок загрузки файлов на результат не влияет. Тип документа определяется по имени файла (слова «инвойс», «счёт-фактура», «спецификация», «упаковочный лист», invoice, packing list и т. п.), а если имя ничего не говорит — по составу колонок: цена и стоимость бывают только в инвойсе, вес и номера мест — только в упаковочном листе. Товар, которого в инвойсе нет, встаёт после инвойсных строк.
- **Режим «построчно»** — каждая строка упаковочного листа становится отдельной строкой таблицы, цена подтягивается из инвойса по артикулу.
- **Расхождения между документами** по количеству, весу или стоимости выделяются **жёлтой заливкой**; математические расхождения (расчёт не сходится со значением в файле) — **розовой**.
- **Недостающие данные** не выдумываются: заполняются только найденные графы, остальные остаются пустыми.
- Строки «Итого / Всего / Total» из документов в таблицу не попадают — в том числе английские варианты «INVOICE TOTAL IN USD» и «Amount» (так подписывают итог по разделу в упаковочных листах).
- **Замечание «Отсутствует в файле»** выводится, только если товар не подтверждён **ни одним** документом соответствующего типа. Отсутствие товара в соседнем инвойсе нормально — каждый инвойс везёт свою часть поставки, — а вот отсутствие в упаковочном листе стоит проверить.

## Поддерживаемые форматы

| Формат | Качество распознавания |
|--------|------------------------|
| XLSX, XLS, CSV | Высокое — таблицы читаются напрямую |
| DOCX, TXT | Хорошее, если данные оформлены таблицей или строками с разделителями |
| PDF | Текстовые PDF читаются построчно; **сканы без текстового слоя не распознаются** (нужен предварительный OCR) |

## Распознавание с ИИ (опционально)

Если приложение запущено через `npm start` (см. «Установка» ниже), загруженные файлы дополнительно прогоняются через Claude — это часто повышает качество распознавания марки/модели/изготовителя и работы со сканами PDF (через отрисовку страниц в изображение). При сбое (сеть, отсутствие сервера) приложение автоматически откатывается на локальный разбор без ИИ — раздел 1 работает даже без него.

Большие документы отправляются на распознавание **частями**: ответ ИИ — это отдельная запись на каждую строку документа, и целиком он в лимит длины одного ответа не помещается. Части режутся по границам строк, каждой передаётся шапка документа, результаты собираются в один список. В строке состояния видно, какая часть обрабатывается.

На GitHub Pages ИИ-распознавание недоступно (там нет сервера, отдаются только статические файлы) — работает обычный локальный разбор.

## Проверка работы

В папке `examples/` лежат тестовые файлы — `invoice_primer.xlsx` и `packing_list_primer.xlsx`. Загрузите оба: приложение объединит дубликаты «Фильтр масляный», распределит брутто места № 1 (150 кг) пропорционально нетто насоса и прокладки (139,535 + 10,465) и выделит жёлтым строку «Прокладка резиновая» — по ней количество в инвойсе (100) расходится с упаковочным листом (90).

# Раздел 2. Проверка ограничений по постановлениям 311, 312, 313

Сверяет коды ТН ВЭД из таблицы товаров с перечнями постановлений Правительства РФ 311, 312 и 313 и возвращает исходную таблицу с добавленными графами.

Перечни берутся **только из файлов, которые загружает пользователь**. Обращений к внешним сайтам нет: и постановления, и таблица товаров разбираются в браузере и никуда не отправляются.

**Это инструмент предварительной проверки, а не замена работе с первоисточником.** Проверяется только код ТН ВЭД. Постановления содержат исключения по происхождению товара, направлению вывоза, таможенной процедуре, назначению груза и статусу отправителя — ничего этого приложение не знает. «Нет» в таблице означает отсутствие совпадения по коду, а не отсутствие ограничений.

## Шаг 1. Тексты постановлений

Загрузите файлы RTF с консолидированными редакциями постановлений — можно все три сразу. Такие файлы выгружаются из справочно-правовых систем: в них текст постановления уже сведён со всеми изменениями, а редакции подписаны маркерами.

Что приложение делает с файлом:

- **определяет номер постановления из текста документа**, а не из имени файла — файл могли переименовать;
- находит приложения с перечнями по графе «Код ТН ВЭД ЕАЭС»;
- отбрасывает перечни, которые не про товары (у постановления 313 приложение № 1 — список стран);
- отбрасывает позиции с пометкой «Позиция исключена»;
- отбрасывает старые редакции позиций и приложений, оставляя действующие;
- собирает исключения, в том числе перенесённые на следующую строку.

После разбора приложение показывает, сколько позиций найдено в каждом приложении. **Если число резко отличается от ожидаемого, разбор сломался** — это главный индикатор исправности.

Ориентиры для проверки (редакция от апреля 2026 года):

| Постановление | Приложений | Позиций |
| --- | --- | --- |
| ПП 311 | 3 | около 124 |
| ПП 312 | 6 | около 179 |
| ПП 313 | 2 | около 64 |

### Если загружены не все постановления

Приложение работает с тем, что есть. По незагруженным постановлениям в графе будет «нет данных», а в итоге — «нет перечня по 313». Пустая проверка не выдаётся за отсутствие ограничений.

### Хранение между сеансами

Разобранные перечни сохраняются в браузере, поэтому при следующем открытии страницы загружать файлы заново не нужно. В этом случае приложение выводит предупреждение **«Данные из предыдущего запуска»** с датой загрузки — постановления могли измениться. Кнопка «Забыть перечни» удаляет сохранённое.

## Шаг 2. Таблица товаров

Таблица в XLSX, XLS или CSV. Обязательна графа с кодом ТН ВЭД.

Подойдёт и таблица, собранная в первом разделе: графа «Код ТН ВЭД ЕАЭС» распознаётся автоматически.

### Как определяются границы таблицы

В реальных спецификациях таблица редко начинается с первой строки: сверху бывает название документа, номер, дата, подпись «Список товаров», а снизу — «Итого», сводные веса и количество мест.

Приложение ищет **строку заголовков** — первую строку, где встречается название графы с кодом ТН ВЭД («Код ТН ВЭД», «ТН ВЭД», «HS code», «Commodity code»). Всё, что выше, отбрасывается.

Товарами считаются строки, где в этой графе стоит код из шести и более цифр. Строки без кода в результат не попадают. После обработки приложение сообщает, в какой строке нашло шапку, из какой графы взяло код и сколько строк отбросило.

### Если заголовка нет

Тогда графа определяется по содержимому. Это ненадёжно, и приложение ведёт себя осторожно.

Рядом с кодом ТН ВЭД почти всегда стоит артикул, который тоже выглядит как длинное число. Перепутать их — значит молча проверить не то и получить сплошные «нет». Поэтому:

- графы с заголовками «Артикул», «Item code», «Код изделия», «Part number», «SKU» исключаются из поиска;
- значения с буквами (`300513672E`) не считаются кодами;
- полные десятизначные коды дают преимущество;
- если несколько граф похожи одинаково, приложение **отказывается выбирать** и просит назвать графу явно.

Надёжнее всего назвать графу «Код ТН ВЭД» или «HS code».

## Результат

Исходная таблица плюс семь граф:

| Графа | Значения |
| --- | --- |
| ПП 311 | да / нет / проверить / нет данных |
| Искл. из 311 | да / нет / проверить |
| ПП 312 | да / нет / проверить / нет данных |
| Искл. из 312 | да / нет / проверить |
| ПП 313 | да / нет / проверить / нет данных |
| Искл. из 313 | да / нет / проверить |
| Итог проверки | словесный вывод |

Результат скачивается в XLSX. Ячейки с «да» подсвечены розовым, «проверить» и «нет данных» — жёлтым. В примечании к ячейке указано, какое приложение и какая позиция сработали. Второй лист книги содержит источник данных, дату проверки, состав загруженных перечней и памятку по чтению.

### Как читать

- **ПП = да, Искл. = нет** — товар подпадает под ограничение;
- **ПП = да, Искл. = да** — позиция выведена из-под ограничения, товар **не** подпадает;
- **ПП = нет** — совпадений в перечне не найдено;
- **ПП = нет данных** — перечень не загружен, проверка не проводилась.

Два «да» подряд читаются не как «двойной запрет», а ровно наоборот. Ориентируйтесь на графу «Итог проверки» — она сводит все три постановления в одну фразу.

### Когда появляется «проверить»

1. **Код товара короче кода перечня.** В файле `8501`, в перечне `8501 53 810 0`. Товарная группа шире позиции — нужен полный код.
2. **Текстовое исключение.** В перечнях встречаются исключения без кодов: «за исключением товаров, указанных в абзаце двадцать седьмом пункта 2». Такое проверяется только вручную.

## Логика сопоставления

Коды нормализуются — остаются только цифры: `8501 53 810 0` → `8501538100`.

Совпадение определяется по префиксу: код товара должен начинаться с кода позиции перечня. Затем так же проверяются исключения этой позиции.

Пример. Товар `8501538100`, позиция `8501 (за исключением 8501 20 000 9, 8501 52 200 1)`:

- `8501538100` начинается с `8501` → **ПП 311 = да**;
- ни с одним из исключений не начинается → **Искл. = нет**;
- итог: подпадает под 311.

### Приложения

Совпадение по любому приложению даёт «да» в общей графе. Какое именно приложение сработало, видно в примечании к ячейке и во всплывающей подсказке.

Учтите юридическую разницу: приложение № 1 к постановлению 311 — запрет на вывоз, приложения № 2 и № 3 — разрешительный порядок. Общая графа их не различает, поэтому при «да» смотрите примечание.

## Ограничения раздела 2

- Проверяется только код ТН ВЭД (см. выше).
- Разбор рассчитан на формат консолидированных RTF из справочно-правовых систем. Другой формат маркеров редакций может распознаться неверно — следите за числом найденных позиций.
- Постановления действуют до 31 декабря 2027 года и не подлежат применению с 1 января 2028 года.

# Раздел 3. Маркировка «Честный знак»

Раздел отвечает на один вопрос: **подлежит ли товар маркировке средствами идентификации**. Ответ ставится в отдельной графе рядом с каждой строкой вашей таблицы.

## Шаг 1. Сводный перечень

Загружается один файл RTF — «Сводный перечень товаров, подлежащих маркировке средствами идентификации» (выгрузка из справочно-правовой системы; перечень составлен разработчиками ВЭД-Инфо по документам Правительства РФ и ФТС России).

Приложение разбирает таблицу перечня по графам: номер, наименование товара, код ТН ВЭД ЕАЭС, код ОКПД 2, срок введения обязательной маркировки, примечание, нормативные документы. Коды ОКПД 2 в проверке не участвуют.

Позиции после заголовка «Эксперименты, проводимые по маркировке отдельных товаров» (в исходном файле выделены жёлтой заливкой) считаются **добровольной** маркировкой: обязанности они не создают и в выводе «требуется» никогда не появляются.

Разобранный перечень сохраняется в браузере и подхватывается при следующем открытии — с пометкой, что данные из прошлого запуска. Кнопка «Забыть перечень» его удаляет.

## Шаг 2. Таблица товаров

XLSX, XLS или CSV произвольного вида. Нужны две графы: с наименованием товара и с кодом ТН ВЭД. Шапку приложение находит само — по названию графы с кодом («Код ТН ВЭД», «ТН ВЭД», «HS code»); графы «Артикул», «Item code» и подобные под код ТН ВЭД не принимаются.

## Результат

Скачивается **копия загруженного файла** — те же листы, строки, значения и оформление — с одной добавленной последней графой «Честный знак»:

| Значение | Когда ставится |
| --- | --- |
| `требуется` | код совпал с позицией обязательной маркировки, срок наступил, оговорок нет |
| `проверьте вручную` | срок ещё не наступил; или в позиции исключение, заданное словами; или позиция охватывает не весь код («из 2309», «в части сушёной продукции»); или код в вашей таблице короче кода перечня |
| `не требуется` | совпадений по коду нет |

Если у сработавшей позиции заполнена графа «Примечание», её текст копируется в ту же ячейку вслед за словом «требуется» — читайте его: чаще всего именно оно выводит товар из-под маркировки («за исключением молочной продукции массой нетто 30 граммов и менее…»).

Когда код совпал только с экспериментом, в графе будет «не требуется» и справочная приписка, какой эксперимент идёт (или проводился) по этому коду.

Какая именно позиция перечня сработала, видно во всплывающей подсказке на экране и в примечании к ячейке выгруженного файла.

## Ограничения раздела 3

- Сверяется **только код ТН ВЭД**. Наименование товара, вид упаковки, объём и масса, назначение, наличие свидетельства о госрегистрации приложению неизвестны — «не требуется» означает отсутствие совпадения по коду, а не отсутствие обязанности маркировать.
- Перечень маркируемых товаров меняется часто: загружайте свежую выгрузку RTF, а не полагайтесь на сохранённую.
- Даты берутся из графы «Срок введения обязательной маркировки». Если в графе несколько дат, берётся помеченная «(начало обязательной маркировки)».
- XLS и CSV пересобираются заново (эти форматы библиотека выгрузки открыть не может), поэтому оформление исходного файла в них не сохраняется — значения и строки сохраняются полностью. Для XLSX выгружается ваш же файл со всеми листами и оформлением.

# Установка

## Запуск с ИИ-распознаванием (раздел 1) и проксирующим сервером

```bash
npm install
set ANTHROPIC_API_KEY=...   # PowerShell: $env:ANTHROPIC_API_KEY = "..."
npm start
```

Сервер (`server.js`) отдаёт статические файлы и поднимает `/api/anthropic` — единственное место, куда попадает `ANTHROPIC_API_KEY`. Опционально задаются `ANTHROPIC_MODEL` (модель Claude) и `PROXY_SECRET`. Порт — переменная `PORT` (по умолчанию 3000).

## GitHub Pages (только статика, без ИИ)

1. Загрузите содержимое этой папки в репозиторий.
2. Откройте **Settings → Pages**.
3. В разделе **Build and deployment** выберите: Source — *Deploy from a branch*, Branch — `main`, папка — `/ (root)`. Нажмите **Save**.
4. Через одну–две минуты приложение будет доступно по адресу `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Либо через командную строку:

```bash
git add .
git commit -m "Добавлен раздел проверки ограничений 311, 312, 313"
git push
```

Локально приложение можно открыть двойным щелчком по `index.html` — сервер не нужен (требуется доступ в интернет для загрузки библиотек с CDN), но раздел 1 будет работать без ИИ-распознавания.

# Используемые библиотеки (CDN)

- [SheetJS](https://sheetjs.com/) — чтение XLSX/XLS/CSV
- [ExcelJS](https://github.com/exceljs/exceljs) — выгрузка XLSX с заливкой и примечаниями
- [pdf.js](https://mozilla.github.io/pdf.js/) — извлечение текста из PDF
- [mammoth.js](https://github.com/mwilliamson/mammoth.js) — извлечение текста из DOCX

# Общие ограничения

- Приложение — помощник декларанта, а не замена проверки: перед подачей ДТ сверяйте данные с первоисточниками.
- Справочник ОКЕИ включает наиболее употребимые единицы; при необходимости список легко расширить в начале файла `app.js` (массив `OKEI`).
- PDF со сложной вёрсткой таблиц могут распознаваться частично — в этом случае приложение сообщит, что данные в файле не найдены.
